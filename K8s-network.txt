6.1

ClusterIP is the default Kubernetes Service type that assigns a stable,
internal virtual IP address to a group of pods, enabling reliable load-balanced communication
only within the cluster. ⁠

Service: go-api
ClusterIP: 10.96.0.50
Port: 80

An application inside the cluster could access:
http://10.96.0.50:80

or

http://go-api:80


6.2

NodePort is a Kubernetes Service type that exposes an application externally by opening a static port
(default range 30000–32767) on every Node's IP address in the cluster.
It functions by building on top of the default ClusterIP service, automatically allocating a ClusterIP
and routing incoming traffic from any node to the appropriate backend Pods.

External Access: Clients can reach the application via http://<NodeIP>:<NodePort> from outside the cluster.

9.1 Ingress

An Ingress object declares HTTP and HTTPS routing rules.

Ingress rules can express this routing configuration.
However, the Ingress object doesn't actually receive HTTP traffic.
You need an Ingress controller that implements those rules.

An Ingress controller may configure a reverse proxy or other load-balancing implementation.
An Ingress controller can perform a related function, but it receives its intended routing configuration through Kubernetes resources.

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: go-api-ingress
spec:
  rules:
    - host: api.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: go-api
                port:
                  number: 80

9.2 Gateway API

Gateway API provides a more expressive and extensible approach to traffic routing.

GatewayClass	- Identifies the implementation/controller managing Gateway infrastructure
Gateway	- Describes a traffic entry point and its listeners
HTTPRoute	- Specifies HTTP routing rules and backend destinations

lesson 10

You might want these security requirements:
- Frontend Pods can contact the Go API.
- Go API Pods can contact PostgreSQL.
- Frontend Pods cannot directly access PostgreSQL.
- Unrelated Pods cannot access your database.

Kubernetes NetworkPolicies can express allowed ingress and egress traffic.


10.1 Ingress versus egress

ingress and egress describe the direction of traffic relative to a selected Pod.

Ingress - Traffic entering the selected Pod
Egress - Traffic leaving the selected Pod

For example, the Go API's PostgreSQL connection is:
- Egress traffic from the Go API Pod.
- Ingress traffic to the PostgreSQL Pod.


10.2 An example NetworkPolicy

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-api
spec:
  podSelector:
    matchLabels:
      app: go-api

  policyTypes:
    - Ingress

  ingress:
    - from:
        - podSelector:
            matchLabels:
              role: frontend

      ports:
        - protocol: TCP
          port: 8080
