lesson 1.1

A Pod can contain:
1. One or more application containers.
2. Shared networking resources.
3. Shared storage volumes.
4. Configuration governing how the containers execute.


lesson 2.1

Containers inside the same Pod share a network namespace.

This means they share:
- A Pod IP address.
- Network interfaces.
- The same TCP/UDP port space.

Containers within the same Pod can communicate through localhost.
Containers in different Pods normally communicate using Pod IP addresses or Services.

lesson 2.3

A sidecar is an auxiliary container that supports a primary application container.

Log processing
Proxying network traffic
Refreshing shared configuration or content
Providing supporting functionality


lesson 3.0

Kubernetes tracks the Pod's overall condition through its status fields.

status:
  phase: Running

The Pod phase represents a high-level summary of its lifecycle.


lesson 3.1

There are five possible Pod phases.

Pending - Kubernetes accepted the Pod, but its containers haven't finished preparation for execution
Running - The Pod is assigned to a node, its containers have been created, and at least one is running or starting/restarting
Succeeded - All relevant containers completed successfully and won't restart
Failed - All relevant containers terminated, and at least one failed
Unknown - Kubernetes cannot determine the Pod's current state
