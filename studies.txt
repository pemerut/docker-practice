and Pods should be able to communicate over the cluster network without requiring
the application to know which physical node hosts the destination.

lesson 4.1

A Pod can disappear and be replaced by a new Pod with a different IP address.
If clients connect directly to those addresses, they must somehow discover replacements whenever the Pod population changes.

A Service provides a stable networking abstraction over a set of backends.

lesson 4.2

Service indentify pods by labels and selectors

apiVersion: v1
kind: Service
metadata:
  name: go-api
spec:
  type: ClusterIP
  selector:
    app: go-api
  ports:
    - port: 80
      targetPort: 8080


lesson 4.3

An EndpointSlice is a Kubernetes API resource describing a set of network endpoints used by Services.
For a normal Service with a selector, the EndpointSlice controller maintains information about matching Pods.

Pod IP addresses.
Ports.
Endpoint readiness conditions.
Node and zone information.

A Service doesn't directly contain all of its backend Pod IPs.
EndpointSlices provide the scalable endpoint representation.

lesson 6

ClusterIP	- Expose an application inside the cluster
NodePort - Expose a Service using a port on cluster nodes
LoadBalancer	- Request an external load balancer from a compatible implementation
ExternalName	- Map a Service DNS name to an external DNS name


6.1

ClusterIP is the default Kubernetes Service type that assigns a stable,
internal virtual IP address to a group of pods, enabling reliable load-balanced communication
only within the cluster. ⁠

Service: go-api
ClusterIP: 10.96.0.50
Port: 80

An application inside the cluster could access:
http://10.96.0.50:80

or

http://go-api:80


6.2

NodePort is a Kubernetes Service type that exposes an application externally by opening a static port
(default range 30000–32767) on every Node's IP address in the cluster.
It functions by building on top of the default ClusterIP service, automatically allocating a ClusterIP
and routing incoming traffic from any node to the appropriate backend Pods.

External Access: Clients can reach the application via http://<NodeIP>:<NodePort> from outside the cluster.
